# PayProof

> Built with Arc Studio. Project memory for future developers and agents.

## What this app does

PayProof checks whether a claimed USDC payment matches the transaction recorded on Arc.
The user enters a transaction hash, the amount the payer claims to have sent, and the
recipient address. The app reads the receipt and USDC transfer logs from Arc over public
JSON-RPC and returns MATCH, MISMATCH, FAILED / PENDING, or UNVERIFIABLE, with a field-by-field comparison.

It is read-only. It never connects a wallet, signs, or broadcasts transactions, and it has no
smart contracts or backend.

## Tech stack

- React 18, Vite, TypeScript, Tailwind CSS, lucide-react icons
- viem v2 for JSON-RPC calls (no wagmi, no wallet connectors)

## Chain and token facts

- Arc Mainnet: chain ID 5042, RPC `https://rpc.mainnet.arc.io`, explorer `https://explorer.arc.io`
- Arc Testnet: chain ID 5042002, RPC `https://rpc.testnet.arc.io`, explorer `https://explorer.testnet.arc.io`
- Gas token is USDC with 18 decimals. ERC-20 USDC at `0x3600000000000000000000000000000000000000` has 6 decimals.
- Native USDC transfers are logged from the system emitter `0xffffFFFfFFffffffffffffffFfFFFfffFFFfFFfE` (18 decimals).
  One log per movement. Do not also count the ERC-20 log, because a single ERC-20 transfer emits both.
- Sources: https://docs.arc.io/arc/references/usdc-system-events

`src/onchain-facts.ts` is the chain registry. It is generated by Arc Studio, so update it
from the source when chain details change, not by hand.

## Key files

- `src/lib/verify.ts`: verification engine. All classification logic lives here.
- `src/lib/share.ts`: builds and reads shareable links (`?tx=…&amount=…&to=…&network=…`).
- `src/App.tsx`: layout, session duplicate counter, auto-run from shared links.
- `src/components/VerifyForm.tsx`: input form.
- `src/components/ResultPanel.tsx`: result display.
- `src/components/ReportModal.tsx`: copyable report.

## Behaviour rules

- A missing receipt is FAILED / PENDING, never proof of failure.
- Multiple transfers to the expected recipient are UNVERIFIABLE, never added together.
- Amounts are compared exactly in base units.
- A session duplicate counter is kept in memory per tab. It is not persisted.

## Running

```bash
bun install
bun run dev        # local development
bun run build      # typecheck and production build to dist/
```
